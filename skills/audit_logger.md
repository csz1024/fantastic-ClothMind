# audit_logger

## 能力
记录系统运行过程中的关键事件和数据变化。

## 触发条件
每个Skill调用、方案生成、用户操作后自动记录。

## 输入
- event_type: 事件类型
- session_id: 会话ID
- operation: 操作详情
- state_before: 操作前状态（可选）
- state_after: 操作后状态（可选）

## 输出
```json
{
  "event_id": "uuid",
  "logged": true,
  "timestamp": "2026-10-07T19:00:00Z"
}
```

## 记录内容
- Skill调用：技能名称、输入摘要、输出摘要、耗时
- 候选商品数量：过滤前后的数量
- 被过滤商品及原因：具体SKU和失败原因
- 选择的SKU：最终进入方案的SKU列表
- 预算计算结果：分项金额和合计
- 锁定与替换操作：用户操作类型和影响的SKU
- 库存变化：库存快照对比
- 方案版本：每次重规划的版本号
- 错误与降级：异常信息和降级措施

## 规则
- 日志中不要重复保存用户原始图片和敏感信息
- 使用结构化JSON格式，便于后续分析
- 每个事件包含时间戳和会话ID
- 错误日志包含堆栈跟踪（如适用）

## 边界
- 不记录用户隐私数据（如人脸、身份证号）
- 不记录完整的商品图片二进制数据
- 日志保留期限由部署环境决定
